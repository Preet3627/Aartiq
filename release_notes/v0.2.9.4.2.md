# v0.2.9.4.2 - 2026-04-23

**Channel:** Stable

## Changes

Critical fix for macOS app launch - the app now works with ad-hoc code signing without requiring an Apple Developer account.

### What's Fixed

| Issue | Status |
|-------|--------|
| App not launching on macOS | Fixed |
| Restricted entitlements error | Fixed |
| AMFI signature validation failure | Fixed |

### The Problem

The app contained restricted entitlements requiring an Apple Developer certificate:
- `com.apple.security.cs.allow-jit`
- `com.apple.security.cs.allow-unsigned-executable-memory`
- `com.apple.security.cs.disable-library-validation`

When built with ad-hoc signing (no Apple Developer certificate), the macOS kernel blocked the app:
```
AMFI: '/Applications/Aartiq.app/Contents/MacOS/Aartiq' is adhoc signed.
amfid: The file is adhoc signed but contains restricted entitlements
```

### The Solution

Removed restricted entitlements from `entitlements.mac.local.plist`. The app now only uses entitlements allowed with ad-hoc signing:

```xml
<dict>
  <key>com.apple.security.network.client</key>
  <true/>
  <key>com.apple.security.network.server</key>
  <true/>
  <key>com.apple.security.files.user-selected.read-write</key>
  <true/>
  <key>com.apple.security.automation.apple-events</key>
  <true/>
</dict>
```

### Still Supported

All features remain functional: network requests, file access, automation (Apple Events), PDF generation, AI commands, WiFi Sync, Siri Shortcuts.

### Note on Apple Developer Certificate

Users with an Apple Developer account can add restricted entitlements back when signing with a valid certificate. For ad-hoc/local development, the simplified entitlements work without issues.
