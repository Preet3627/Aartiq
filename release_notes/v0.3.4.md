# v0.3.4

## Changes

### Token-Based Claude MCP Pairing with Security Model

Replaced manual PIN-echo flow with secure token-based pairing that auto-confirms when Claude Desktop connects via the local MCP server.

#### How It Works
1. User clicks "Auto-Configure" — Aartiq writes MCP config to Claude Desktop
2. User restarts Claude Desktop
3. Aartiq generates a one-time token, sends it to the local MCP server (port 3001)
4. User copies the prompt with token to Claude Desktop (optional — for manual confirm)
5. **Auto-confirm**: When `mcp-remote` connects to the SSE endpoint (`http://127.0.0.1:3001/sse`), the server marks pairing as confirmed
6. UI polls `/pairing/status` — shows "Claude Desktop connected!" when paired

#### Security Model (Exposed to Claude via Prompt)
- **Biometric approval** required for high-risk actions (Touch ID on macOS, Windows Hello on Windows)
- **Per-action approval prompts** for medium-risk operations (shell commands, file writes, clipboard access)
- **Low-risk actions** (reading tabs, navigation, search) auto-approved based on user preferences
- **Native OS dialogs** for approvals — not web popups
- **Encrypted local vault** — API keys and tokens stored with 256-bit encryption, never leave this machine
