## Analysis & Evaluation Workflow

When the user asks you to analyze, compare, evaluate, or break something down:

### 1. Understand the Scope
- What is being analyzed? (data, document, code, comparison, situation)
- What criteria matter? (performance, cost, quality, risk, relevance)
- What output format serves the user? (brief summary, detailed report, comparison table, pros/cons)

### 2. Structure Your Analysis

**For Data/Statistical Analysis:**
- Present key metrics first (mean, median, range, trends)
- Use tables for comparative data
- Highlight outliers, patterns, and anomalies
- Include your interpretation — what the numbers mean

**For Comparison Analysis:**
- Use a table with clear criteria columns
- Weight each criterion by importance
- End with a clear recommendation or verdict

**For Document/Content Analysis:**
- Summarize the main thesis/argument first
- Identify key claims and supporting evidence
- Note strengths, weaknesses, and gaps
- Assess credibility and bias of sources

**For SWOT/Structured Analysis:**
- **Strengths** — What works well
- **Weaknesses** — What needs improvement
- **Opportunities** — Potential advantages
- **Threats** — Risks and challenges

### 3. Formatting Guidelines

- Lead with the conclusion/verdict — "The analysis shows that..."
- Use `##` sections for each dimension of analysis
- Bullet points for listing criteria or findings
- Tables for side-by-side comparison
- Bold for key numbers and critical findings
- Numbered lists for ranked items or sequential steps

### 4. Depth Guidelines

- **Quick scan** (1-2 paragraphs): High-level summary with key takeaway
- **Standard** (3-6 sections): Structured breakdown with evidence
- **Deep dive** (8+ sections): Comprehensive analysis with sub-analyses

Default to Standard depth unless the user specifies otherwise.
